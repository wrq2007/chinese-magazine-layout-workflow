# 成本路由：哪一步该谁做（2026-09 实测）

> 背景：一篇 4 页稿走完全流程，粗算 **40–50 万 token**，其中真正"非模型不可"的推理不到两成。
> 省钱的顺序是：**先变脚本 → 再转本地 → 最后才留给我**。

## 实测开销构成

| 项目 | 单次消耗 | 说明 |
| --- | --- | --- |
| 每轮重读技能与档案 | **≈40k token/次全读** | AGENTS 8.3KB + layout-qc SKILL 11.6KB + 错误档案 33.2KB + … 合计 66KB |
| 复核模型自己量测（旧做法） | **≈40–80k/次** | 它要读 PDF、写 PyMuPDF 脚本、多轮推理 |
| 独立复核（2026-09-20 起：零上下文子代理） | 量测已脚本化后 ≈5–10k | **与排版用的是同一个 API key，换复核者不省额度**；省的是维护与等待 |
| 云端视觉 API（我脚本调） | 5k–12k/页 | 5–6 页 = 30k–70k |
| 本地模型复核 | **0** | 一页 40–100 秒 |

## 路由表

### A 级：变成脚本（不花 token，质量最高）

凡是"读数、比对、判定"的活，全部脚本化。一条命令出结论：

```bash
python qc-all.py <成品.pdf> --sources 源文1 源文2 ...      # 一项一判，4–5 秒跑完
```

它内部串起 10 项：页面盒/出血/DPI、实际边距、内嵌字体、装饰一致性、孤字成行、总墨量 TAC（含"贴线"提醒）、
**文字墨色色版构成**、**输出意图/色彩管理**、**图注对比度/残字/间距**、文字保真。
判定分三档：`[合格]` / `[注意]`（WARN，不算不合格但要记）/ `[需处理]`（FAIL）。
**交给复核模型时只给它这张表，不要让它自己去量**——这一步就把 40–80k 砍到 5–10k。

### B 级：转本地模型（质量不降）

| 任务 | 怎么做 |
| --- | --- |
| 版面审美复核 | `ask-local-model.py`（已在用） |
| **素材读图**：识别图片内容、界面元素、曲线通道 | 同一支脚本，本地模型带 mmproj 视觉 —— **不要再用云端视觉 API** |
| 图注/说明文字**草案** | 本地出稿，我只核事实与定稿 |
| 复核里"看图判断"的部分 | 同上 |

### C 级：留在云端模型（转了会掉质量）

- 理解用户**到底要什么**、把模糊需求拆开、决定要不要问
- 写 InDesign 脚本与排错（"图注折行把人名拆开""单位混算"这类坑，本地 27B 未验证）
- **跨文件一致性**：「这条规则还有哪些同类实例」——实测本地模型与复核模型**都漏过**，
  靠脚本枚举才可靠
- 报告自检：「我说改好了，是不是真的」

## 三件比"转模型"更省的

1. **降推理档位**：配置里的 `model_reasoning_effort`（本项目原为 high）。日常排版用 medium 甚至 low，
   只在排错时升上去。
2. **上下文瘦身**：开工只读 `mistakes-brief.md`（2KB），**不要每轮全读 `mistakes-log.md`（33KB）**；
   它是本工作流最大的单笔上下文开销。
3. **少来回**：每多一轮对话，那 40k 上下文就再发一遍。需求一次问清比事后补三回便宜得多。
   另外：送模型的页面图先缩到 150dpi／长边 ≤1500 就够用（早期送 300dpi 大图，每页多花近一倍）。

## 粗算收益

| | 优化前 | 优化后 |
| --- | --- | --- |
| 我的上下文 | 10 轮 × 40k ≈ 400k | 瘦身到 12k → 120k |
| 复核（模型自己量） | 60k | 10k（只读 `qc-all` 的表） |
| 视觉复核 | 50k | **0**（转本地） |
| **合计** | **≈51 万** | **≈13 万（省约 75%）** |

省掉的是"模型在干脚本该干的活"和"重复灌上下文"，不是省掉推理——所以质量不降。


## 更正：换掉外部复核工具链 ≠ 省钱（2026-09-20）

原先把"交另一个工具链复核"当成一次额外开销，现在要更正一句：
那次复核和排版**走的是同一个 DeepSeek API key**，所以换掉它**并不减少额度消耗**，
子代理一样按 token 计费。换掉它的收益是另外三条：

1. **少一个活动部件**：不用维护第二个 harness、第二份凭据、第二套技能目录；
2. **复核者与排版同工作区、同脚本、同规则**，能直接读项目文件，也不必每次写"请求文件"；
3. **一次能覆盖多件成品**（实测：同一轮里把发刊词与通透一起审了）。

真正的省法没变，还是那三条：**先变脚本 → 再转本地 → 最后才留给云端模型**。
本次改版的实质就是——把复核者抓到的独家发现固化进 `qc-all`，
让下一轮**谁都不必再去重复那一次劳动**。
