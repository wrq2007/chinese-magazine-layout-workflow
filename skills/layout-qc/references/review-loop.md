# 排版完成后的复核闭环

> 2026-09 在《通透》上跑通并定型。核心思想：**审的人、改的人、核的人分开**，
> 而且"核"这一步必须**换一条技术路线**，不能把同一个检查跑两遍。

## 四步

```
⓪ 排版之前：文字审计（本地模型出初筛 → Codex 核实 → 用户确认）
      ↓
① Codex 初次排版完成
      ↓
② 交本地多模态模型审一次（审美与规范）
      ↓
③ Codex 按意见修改
      ↓
④ 交另一个模型复核"是否真的改到位"（不回调②的模型）
```

为什么第 ④ 步要换模型：本轮实测，②提的 8 条里 Codex 改了 6 条，
④ 逐条量下来发现**只有 4 条真的满足**——其中 1 条落差纹丝没动、
还指出 Codex"只改被点到的那一处、漏了同类另一处"，反而把一致性搞得更差。
同一个模型自审是查不出这类连锁错误的。

## 给"审"的那一步（本地模型）

用 `scripts/ask-local-model.py`。要点：

1. **必须有前情提要**：模型不了解项目就会瞎提（比如要求加页码、建议左右边距同宽）。
   把规格、硬规矩、已定事项写进一份 `brief.md`，每次调用自动注入。
2. **必须有长期记忆**：本地 llama-server **无状态**，停服务就忘。
   把"已确认的决定 + 已改过的问题 + 有意保留的"写进 `memory.md`，每次一起注入；
   每轮复核后追加新结论，它下次就不会重复提。
3. **推理模型要给足 max_tokens**：返回里有 `reasoning_content` 的那种，
   给 1800 会被思维链吃光、正文为空（`finish_reason=length`）。**给 6000**。
4. **明确禁止它逐字抄录文字**：图片会被缩放，小字必读错。文字一致性另走
   `check-text-fidelity.py`（PDF 抽字核对）。
5. 问法要收窄：只审审美与规范，按页列 0–3 条，格式"问题→为什么→怎么改"，
   按优先级排序。不要让它写全面报告——那是废话。

## 给"核"的那一步（另一个模型）

写一份**请求文件**而不是临时提问，里面包含：

- 上一轮的意见清单（逐条编号）
- Codex 每条的处理（已改 / 未改，未改的写清理由）
- 明确的核对要点（例如"中缝应为 25.5mm""折行点不应拆开「左侧」"）
- 背景与禁区（同 brief）
- 输出格式：`【一】逐条核对` + `【二】新增问题`
- **一条元指令**：判断几何问题时**用程序量毫米**（PyMuPDF 读包围盒），
  不要凭看图估

然后 `dsh --profile headless "<读请求文件并按它做>"`。

## 两条血泪教训（务必遵守）

1. **改规则要改所有同类实例。** 收到"第 4 页那条线不该有"，就要问"还有哪些页是同一情况"，
   用脚本全篇枚举，一次改完。只改被点到的那一处，会让同类元素一半有一半没有，比改前更糟。
2. **报"已改"前后必须同口径量。** "文本框边框底边"与"文字着墨底边"差约 1mm，
   混着比会得出"落差变小了"的错误结论（实测前后都是 6.23mm）。
   报告里写明用的是哪种口径。

## 目录约定（本项目）

```
<项目>\_qwen\
  brief.md              前情提要（稳定，少改）
  memory.md             长期记忆（每轮追加）
  ask-qwen.py           调用脚本（= ask-local-model.py 的封装）
  transcript\           每次问答的完整记录
  第N轮-qwen意见.md      当轮意见 + Codex 处理
  第N轮-dsh复核.md       复核结论 + 追加修改
```

把 `_qwen\` 放在刊物根目录（本项目是 `E:\杂志\`），不要放进出品目录——
出品目录只留 `.indd` 与印刷 PDF。
