# 排版完成后的复核闭环

> 2026-09 在《通透》《序言》《发刊词》上跑通并定型，2026-09-20 做过一次 A/B 后改版。
> 核心思想：**审的人、改的人、核的人分开**，而且"核"必须是
> **零上下文的陌生复核者 + 另一条技术路线**，不能把同一个检查跑两遍。

## 四步

```
⓪ 排版之前：文字审计（本地模型出初筛 → 核实 → 用户确认）
      ↓
① 初次排版完成
      ↓
② 交本地多模态模型审一次（审美与规范）
      ↓
③ 按意见修改
      ↓
④ 交「冷启动复核子代理」独立复核（零上下文，不回调 ②）
```

## ④ 为什么是"冷启动子代理"

复核者的全部价值是一句话：**一个不知道我怎么想的审查者，用另一条路把成品重新量一遍**。
2026-09-20 拿同一份成品、同一份盲审任务书做过一次 A/B（独立的外部工具链 vs 零上下文子代理）：

| | 外部工具链复核 | 冷启动子代理 |
| --- | --- | --- |
| 耗时 | 约 7 分钟 | 约 15 分钟 |
| 覆盖面 | 发刊词 6 条 | 发刊词 4 条 + 通透 7 条 |
| 独家发现 | ① 文字是**三色版叠浅色**（K=0）② PDF **无输出意图/ICC** | ① 图注 K62 对纸白**只有 4.07:1** ② 图注折行后剩单个西文词 ③ 9/10 位图**超 300% 墨量** |
| 数值准确度 | 背景 TAC 报 190.2%，**实测 297.3%（错）** | 报 297.6%（对） |

结论：覆盖面互有胜负、准确度互有胜负，**没有哪一边明显更强**。
那就换成子代理——它和排版在同一个工作区、同一套脚本、同一份项目规则，
少维护一个工具链和一份凭据，而且一次能覆盖多件成品。

**但比"用谁"更重要的是这一条：两边抓到的独家发现都要立刻固化成 `qc-all` 的检查项。**
复核者的价值是随"它的发现被脚本吸收"而递减的；只有把发现变成脚本，
下一轮才不需要再叫任何人去重复同样的劳动。这次 A/B 之后新增了三项检查
（文字墨色色版构成、输出意图、图注对比度/残字/间距），并给 TAC 加了"贴线"提醒。

## 怎么开一个合规的冷启动复核

1. 写一份**盲审任务书**（放在工作区 `work\<NN>-<篇名>\`，**不要放进出品目录**），包含：
   对象、印刷规格判据、**已知前提**（哪些是设计决定、不是缺陷）、输出格式、方法要求。
   已知前提不写全，复核者就会把"用户已经拍板的事"重新提一遍。
2. 派生子代理时用**零上下文**（`fork_turns="none"`），它才会真正独立。
3. 任务书里必须有三条硬约束：
   - **严禁读取本地模型的 `memory.md` / 历次意见目录**——读了就不算独立复核；
   - **严禁调用本项目现成的质检脚本**，必须自己写量测代码，用另一条技术路线；
   - **不许用模型读图核对文字**（图片必被降采样），几何一律程序化量测。
4. **它报的每个数，我要自己复算一遍再采信**。这次就是靠复算才发现外部工具链的
   TAC 数字是错的——复核结论不是权威，只是线索。

## 已经固化进 qc-all 的检查（复核者不必再提这些）

| 项 | 脚本 | 判定线 |
| --- | --- | --- |
| 页面盒 / 出血 / 图像 DPI | `check-pdf-print.py` | TrimBox = 成品尺寸；出血 3mm；位图 ≥300dpi |
| 实际边距（墨迹反推） | `check-pdf-print.py` | 不小于版心要求 |
| 内嵌字体 | `check-pdf-print.py` | 100% 内嵌 |
| 装饰元素一致性 | `check-accent-rules.py` | 同类装饰同规格 |
| 孤字成行 | `check-orphan.py` | 无段落以 1–2 字收尾 |
| 总墨量 TAC | `check-tac.py` | 铜版纸 300%；>300% 记"贴线"，>330% 或成片 >2% 判不合格 |
| **文字墨色（色版构成）** | `check-text-ink.py` | 不许四色黑；反白/浅色小字不许用多色版叠浅色 |
| **输出意图 / 色彩管理** | `check-output-intent.py` | 必须有 /OutputIntent 或内嵌 ICC（PDF/X-4） |
| **图注：对比度 / 残字 / 间距** | `check-caption.py` | 对比度 ≥4.5:1；末行不许剩孤字或单个西文词；间距离散 ≤0.5mm |
| 文字保真 | `check-text-fidelity.py` | 从 PDF 抽字与源文对照 |

## 给"审"的那一步（本地模型）

用 `scripts/ask-local-model.py`。要点：

1. **必须有前情提要**：模型不了解项目就会瞎提（要求加页码、建议左右边距同宽）。
   把规格、硬规矩、已定事项写进 `brief.md`，每次调用自动注入。
2. **必须有长期记忆**：本地 llama-server **无状态**，停服务就忘。
   把"已确认的决定 + 已改过的问题 + 有意保留的"写进 `memory.md`，每次一起注入；
   每轮复核后追加新结论，它下次就不会重复提。
3. **推理模型要给足 max_tokens**：给 1800 会被思维链吃光、正文为空。**给 6000**。
4. **明确禁止它逐字抄录文字**：图片会被缩放，小字必读错。文字一致性另走
   `check-text-fidelity.py`（PDF 抽字核对）。
5. 问法要收窄：只审审美与规范，按页列 0–3 条，格式"问题→为什么→怎么改"，
   按优先级排序。不要让它写全面报告。

## 两条血泪教训（务必遵守）

1. **改规则要改所有同类实例。** 收到"第 4 页那条线不该有"，就要问"还有哪些页是同一情况"，
   用脚本全篇枚举，一次改完。只改被点到的那一处，会让同类元素一半有一半没有，比改前更糟。
2. **报"已改"前后必须同口径量。** "文本框边框底边"与"文字着墨底边"差约 1mm，
   混着比会得出"落差变小了"的错误结论（实测前后都是 6.23mm）。报告里写明用的是哪种口径。

## 目录约定（本项目）

```
<刊物根>\                 E:\杂志\
  _qwen\
    brief.md              前情提要（稳定，少改）
    memory.md             长期记忆（每轮追加）
    ask-qwen.py           调用脚本
    transcript\           每次问答的完整记录
    第N轮-qwen意见.md      当轮意见 + 处理
  产出目录\                只留 .indd 与印刷 PDF
```

工作区侧：

```
work\<NN>-<篇名>\
  盲审任务书-<篇名>.md     复核者要读的那一份（含已知前提与禁区）
  冷启动复核-<篇名>.md     复核结论
  measure\                复核者自建的量测脚本与原始输出
```

`_qwen\` 与 `work\` 都**不要**放进出品目录——出品目录只留 `.indd` 与印刷 PDF。
