# 排版成品质检

## 核心立场

> ⚠️ **省上下文**：开工前只读 `references/mistakes-brief.md`（2 分钟版，15 条必知坑）；
> 细节才去查 `references/mistakes-log.md`（33KB 完整档案，**不要每轮全读**——它是本工作流最大的上下文开销）。

交付前必须**量成品**，不能采信排版软件的自述，也不能采信模型的印象。

- 用「像素尺寸 + DPI」反推物理尺寸：这是抓出「页面单位搞错、导出尺寸错」的唯一可靠手段。
- 比例、留白、元素边界用像素扫描量。**不要问视觉模型比例**——实测它会把 16% 说成 48%，把角落排版说成"上下两栏"。
- **视觉模型不用于核对文字。** 图片在送进模型前会被降采样，小字随之失真——实测把署名「翟翊翔」读成「曹玥玥」、
  把图注「nomadict」读成「nomadicst」。若采信这种读数去回改，会把对的改成错的。
  文字一致性只有一条硬路子：**从 PDF 里抽字符**（`page.get_text()`）与源文对照。
- 视觉模型的正当用途只剩两件：**描述"看到了哪些元素"**、**判断整体观感与结构**（留白、层级、元素是否被压/越界）。
  即便是这两件，几何量也一律以程序化扫描为准（见上一条）。
- 成品上的一切事实（人名、日期、校训、机构名、数字）必须回到原始素材独立核实。模型记忆一律不算证据。

## 流程

1. **量尺寸**：
   `powershell -ExecutionPolicy Bypass -File <skill>/scripts/measure-export.ps1 -Path <导出件> -ExpectedWidthMm 297 -ExpectedHeightMm 420`
2. **量版面**：读上一步输出的「全宽色带」与「文字带」——判断色块边界位置、文字是否压边、是否挤在一角、行距是否均匀。
3. **读内容（字符级，不许用视觉模型）**：
   `python <skill>/scripts/check-text-fidelity.py <成品.pdf> <源文件> [源文件2 ...]`
   从 PDF 抽字符与源文对照，查缺字、错字、被改动的标点。视觉模型看的是降采样后的图，读小字会错——不采信。
4. **改与复检**：回改源文件 → 重新导出 → 从第 1 步重跑。**迭代上限 3 轮**；仍不达标就列出未解决项和原因，不许用"整体不错"掩盖。
5. **报告**：写数字和证据（像素、行区间、百分比、实测色值），不写形容词。

## 质检的分级（别一律上重手段）

不是每一步都值得开独立审查或写文件——过度质检本身是浪费。按节点分配：

| 节点 | 方式 | 产物 |
| --- | --- | --- |
| 版式规则核对（版心/栏/行距） | **脚本自动量** | 控制台输出 |
| 尺寸、出血、内嵌字体 | **脚本自动量** | 控制台输出 |
| 框重叠 | **脚本自动查** | 控制台输出 |
| 文字内容与文案一致性 | **PDF 抽文核对（字符级，脚本）** | 控制台输出 |
| 元素有无被压/越界、留白是否成立 | 局部放大图 + 视觉模型（**只判观感，不读字**） | 消息（临时件，核完即弃） |

**交付件只有两样：`.indd` + 印刷用 `.pdf`**（2026-09-19 用户定的规矩）。
预览图、联系表、局部放大图都只是核查过程中的**临时件**——需要看图时临时生成到 `_build`，
核对完就清理，不留在交付目录里。要"给用户看效果"时，直接在对话里贴图即可，不必落盘留存。
| 成品整体观感与结构问题 | 独立视角复看（编辑 / 视觉 / 技术各过一遍） | 结论写进报告 |

**铁律**：拿到任何质检结论后，**先按结论把问题改完，再汇报**"改了什么 + 复查结果"。
直接把原始结论抛给用户而不修复，等于没做质检。

## 三视角终审（重大交付前）

同一份成品，用三个互相独立的视角各看一遍，不要混在一次描述里：

1. **编辑视角**：文字有没有错、漏、断层——**用 `check-text-fidelity.py` 走 PDF 抽文查，不用视觉模型**；
   标题层级与阅读顺序是否成立；图注是否与图对应。
2. **视觉视角**：焦点是否唯一、层级是否跨档、留白与节奏是否成立、颜色是否克制。
3. **技术视角**：尺寸/出血/分辨率/字体嵌入/框重叠/颜色模式是否符合交付要求。

三个视角的结论分开写，冲突时以"媒介约束 > 信息传达 > 风格偏好"的顺序裁决。

### 复核闭环（排版完成后，2026-09 定型）

**审的人、改的人、核的人分开**：

```
Codex 排版 → 本地多模态模型审 → Codex 改 → 另一个模型复核（不回调前一个）
```

第 ④ 步要**逐条量毫米**核"是否真的改到位"，不要凭看图。本轮实测：第 ② 步提 8 条、
Codex 改 6 条，第 ④ 步量下来**只有 4 条真满足**，还抓出"只改被点到的那一处、漏了同类另一处"。
做法、提示词要点与两条血泪教训见 [references/review-loop.md](references/review-loop.md)。

## 脚本

`scripts/measure-export.ps1`：输出像素尺寸、DPI、反推物理尺寸与目标偏差、主色调、全宽纯色带区间、亮色文字带包围盒（均附毫米坐标）。

`scripts/list-pdf-fonts.ps1`：列出 PDF 实际使用的字体名（含压缩对象流）。交付前用它确认字体是否嵌入；调研他人成品用字时用它取证，不要凭印象猜字体名。

`scripts/check-overlap.jsx`：在 InDesign 里逐页找出「文本框互相重叠」「文本压在图片/色块上」。**文本框是绝对定位的，压在一起不会给任何提示**——排完必查这一项。文本↔文本一律是问题；文本↔图片可能是封面类的有意叠压，需人工判断。

`scripts/check-layout-rules.ps1`：**从导出的成品图反向核对版面规则**——量出栏数、栏宽、栏距、正文行高（并推算字号）与文本区左右边界，和设计规格逐项比对。用于确认"设计意图"和"成品"是否真的一致（栏宽差 2mm、栏距跑掉 1mm 这类问题肉眼看不出来）。
⚠️ **本脚本目前跑不通**（报 `op_Subtraction` on `System.Object[]`，2026-09 实测）。页边距类检查先用下面的 `check-pdf-print.py` 顶上。

`scripts/check-pdf-print.py`：**PDF 印前量测（推荐入口）**——`python check-pdf-print.py <pdf>`。逐页给出
MediaBox / TrimBox / 四边出血、内嵌字体的子集名与所在页、每张置入图的有效 DPI、以及用**墨迹包围盒反推的实际边距**。
比在图上量更硬：读的是 PDF 自己的页面盒。判定线：TrimBox 必须等于成品尺寸、四边出血 3mm、图像 ≥300dpi（理想 350dpi）。

`scripts/check-text-fidelity.py`：**文字保真核对（文字一致性的唯一手段）**——`python check-text-fidelity.py <成品.pdf> <源文件> [源文件2 ...]`。
从 PDF 抽字符与源文对照，给出三层结论：A 字符与顺序完全一致；B 字符集一致（没增没删没改，只是版面换了阅读顺序）；
C 有字符层面差异（列出多重集差与差异位置）。一篇文章的文字常来自多个源文件（正文 md + 作者信息 txt），全部按顺序拼起来再比。
同时输出 `& —— …… “ ” ， 、 ： ？ ！ 【 】` 等易被改坏字符的计数表。

`scripts/verify-page-crop.py`：**局部放大复核（只判观感，不读字）**——`python verify-page-crop.py <pdf> <页号> <x0> <y0> <x1> <y1> "<问题>"`（坐标 mm，相对成品框）。
把指定区域按 300dpi 裁下来交给视觉模型，问一个聚焦问题，例如"这页下半部分是不是留白过大""这块图有没有被压扁""文字有没有被线条压住"。

`scripts/check-tac.py`：**总墨量 TAC 量测**——`python check-tac.py <pdf>`。从 PDF 抽出置入的位图，
按 CMYK 四色之和算总墨量，报平均/最大/超线像素占比。判据：**最大 >330% 或超 300% 的像素 >2%** 才算不合格
（JPEG 边缘振铃会让个别像素略高）。这一项只有量才看得见——常规验收全绿时它仍可能成片越线。

`scripts/check-orphan.py`：**孤字成行检查**——`python check-orphan.py <pdf>`。按"段首 2 字缩进"把行分组为段落，
报出末行 ≤2 字的段落（只统计正文实际字号，避免把两字小标题误判）。容忍度：末行 3–4 字可接受，**1–2 字必须处理**。

`scripts/check-accent-rules.py`：**装饰元素一致性**——`python check-accent-rules.py <pdf>`。
量出全篇所有细长填充矩形（分割线/竖线），按「宽 × 粗 × 颜色」分组，**同类出现两种以上规格就报不一致**。
装饰线最容易"每页一个规格"：单看每页都合理，翻页对比才露馅。

`scripts/ask-local-model.py`：**交本地模型审版面**——`python ask-local-model.py <pdf> --brief 前情提要.md --memory 长期记忆.md`。
把两份 markdown（项目规格＋已确认的决定）与页面图一起送进本地多模态端点。
本地 llama-server 无状态、"记忆"只能靠每次注入文件；推理模型要把 `--max-tokens` 给到 6000，否则思维链吃光额度、正文返回空。

`scripts/qc-all.py`：**一条命令出验收表（推荐入口）**——`python qc-all.py <pdf> --sources 源文...`。
内部串起页面盒/出血/DPI、实际边距、内嵌字体、装饰一致性、孤字成行、总墨量、文字保真，逐项下判定，
4–5 秒输出一张「项 / 实测 / 判定」表。**成本路由的关键**：交给复核模型时只给它这张表，
不要让它自己去读 PDF、写量测脚本——那一步单次要 40–80k token，改成读表只需 5–10k。

`scripts/audit-text.py`：**排版之前的文字审计**——`python audit-text.py <源文.md>`。
查错别字、语法、标点、用词，**由本地模型出初筛（0 费用），Codex 逐条核实后输出成表给用户确认**。
模型报出的条目**未经核实不得采信**（容易把口语化表达当错误），确认后的改动要同步回源文——
否则下次从源文重建会把修改冲掉。
**不要用它核对文字内容**——图片会被降采样，小字必然读错。另外长文本页整页提问会因思维链吃光 token 返回空，拆成上下两块就能问出来。

`scripts/check-contrast.ps1`：**检查"文字压在图上"的对比度**——按 WCAG 相对亮度算文字色与背景的对比度，报告最差位置与低于底线的比例。阈值：正文 ≥ 4.5:1，大标题 ≥ 3:1。带图背景的封面/序言/图版配文必查；实测过"看上去能读、开印会糊"的情况（最差 2.31:1、38.6% 区域不达标）。

`scripts/check-cjk-typography.jsx`：**中文排印规范检查**——避头尾（行首/行尾禁则）、引号是否成对、破折号是否用了 ——、省略号是否用了 ……、是否混用半角标点、首行缩进是否统一、中西文字体是否分离、每行字数是否落在 25–35 字。排完中文正文必跑；这几项肉眼很难查全。

`scripts/compare-text.py`：**（非标准流程，按需使用）** 逐字比对工具——把成品文字与源文件做 diff。
按用户要求，它**不再进入例行验收**：只要守住"文本只复制粘贴、不改一个字"这条不变式，就不需要事后比对。
仅在怀疑文本被改动时（例如不是由脚本从文件灌入、而是中途手工处理过）才拿出来用。

读结果时注意两个口径：

- **页面墨迹边界**包含页码、标题、图版，不等于文本版心；要核对版心请看「文本区」那一段。
- 栏数少于设计值时，先判断是"文案没填满"（正常留白）还是"文本框丢了"（缺陷）——脚本会标 ⓘ 而不是 ★。

调用提醒：本机 PowerShell 执行策略为 Restricted，必须用 `powershell -ExecutionPolicy Bypass -File ...` 调用；直接 `.\script.ps1` 会被拒绝。

## 多页成品（杂志、画册）

逐页导出为页序命名的图片再逐页跑量测，然后额外比对跨页一致性：版心左右边界是否逐页对齐、页眉页脚基线是否跳动、跨页图是否出血连续、目录页码与内文实际页码是否一致。检查细则见 [references/checklist.md](references/checklist.md)。
