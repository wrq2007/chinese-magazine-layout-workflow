# 排版成品质检

## 核心立场

交付前必须**量成品**，不能采信排版软件的自述，也不能采信模型的印象。

- 用「像素尺寸 + DPI」反推物理尺寸：这是抓出「页面单位搞错、导出尺寸错」的唯一可靠手段。
- 比例、留白、元素边界用像素扫描量。**不要问视觉模型比例**——实测它会把 16% 说成 48%，把角落排版说成"上下两栏"。
- 视觉模型只用于两件事：**逐字转录**成品上的文字；描述"看到了哪些元素"。提问时必须要求它区分「看清了」和「看不清」，禁止补全。
- 成品上的一切事实（人名、日期、校训、机构名、数字）必须回到原始素材独立核实。模型记忆一律不算证据。

## 流程

1. **量尺寸**：
   `powershell -ExecutionPolicy Bypass -File <skill>/scripts/measure-export.ps1 -Path <导出件> -ExpectedWidthMm 297 -ExpectedHeightMm 420`
2. **量版面**：读上一步输出的「全宽色带」与「文字带」——判断色块边界位置、文字是否压边、是否挤在一角、行距是否均匀。
3. **读内容**：让视觉模型逐字抄写全部文字，与预期文案逐行 diff，查缺字、错字、豆腐块。
4. **改与复检**：回改源文件 → 重新导出 → 从第 1 步重跑。**迭代上限 3 轮**；仍不达标就列出未解决项和原因，不许用"整体不错"掩盖。
5. **报告**：写数字和证据（像素、行区间、百分比、实测色值），不写形容词。

## 质检的分级（别一律上重手段）

不是每一步都值得开独立审查或写文件——过度质检本身是浪费。按节点分配：

| 节点 | 方式 | 产物 |
| --- | --- | --- |
| 版式规则核对（版心/栏/行距） | **脚本自动量** | 控制台输出 |
| 尺寸、出血、内嵌字体 | **脚本自动量** | 控制台输出 |
| 框重叠 | **脚本自动查** | 控制台输出 |
| 文字内容与文案一致性 | 视觉模型逐字复读 + 与预期 diff | 消息 |
| 成品整体观感与结构问题 | 独立视角复看（编辑 / 视觉 / 技术各过一遍） | 结论写进报告 |

**铁律**：拿到任何质检结论后，**先按结论把问题改完，再汇报**"改了什么 + 复查结果"。
直接把原始结论抛给用户而不修复，等于没做质检。

## 三视角终审（重大交付前）

同一份成品，用三个互相独立的视角各看一遍，不要混在一次描述里：

1. **编辑视角**：文字有没有错、漏、断层；标题层级与阅读顺序是否成立；图注是否与图对应。
2. **视觉视角**：焦点是否唯一、层级是否跨档、留白与节奏是否成立、颜色是否克制。
3. **技术视角**：尺寸/出血/分辨率/字体嵌入/框重叠/颜色模式是否符合交付要求。

三个视角的结论分开写，冲突时以"媒介约束 > 信息传达 > 风格偏好"的顺序裁决。

## 脚本

`scripts/measure-export.ps1`：输出像素尺寸、DPI、反推物理尺寸与目标偏差、主色调、全宽纯色带区间、亮色文字带包围盒（均附毫米坐标）。

`scripts/list-pdf-fonts.ps1`：列出 PDF 实际使用的字体名（含压缩对象流）。交付前用它确认字体是否嵌入；调研他人成品用字时用它取证，不要凭印象猜字体名。

`scripts/check-overlap.jsx`：在 InDesign 里逐页找出「文本框互相重叠」「文本压在图片/色块上」。**文本框是绝对定位的，压在一起不会给任何提示**——排完必查这一项。文本↔文本一律是问题；文本↔图片可能是封面类的有意叠压，需人工判断。

`scripts/check-layout-rules.ps1`：**从导出的成品图反向核对版面规则**——量出栏数、栏宽、栏距、正文行高（并推算字号）与文本区左右边界，和设计规格逐项比对。用于确认"设计意图"和"成品"是否真的一致（栏宽差 2mm、栏距跑掉 1mm 这类问题肉眼看不出来）。

`scripts/check-contrast.ps1`：**检查"文字压在图上"的对比度**——按 WCAG 相对亮度算文字色与背景的对比度，报告最差位置与低于底线的比例。阈值：正文 ≥ 4.5:1，大标题 ≥ 3:1。带图背景的封面/序言/图版配文必查；实测过"看上去能读、开印会糊"的情况（最差 2.31:1、38.6% 区域不达标）。

`scripts/check-cjk-typography.jsx`：**中文排印规范检查**——避头尾（行首/行尾禁则）、引号是否成对、破折号是否用了 ——、省略号是否用了 ……、是否混用半角标点、首行缩进是否统一、中西文字体是否分离、每行字数是否落在 25–35 字。排完中文正文必跑；这几项肉眼很难查全。

`scripts/compare-text.py`：**（非标准流程，按需使用）** 逐字比对工具——把成品文字与源文件做 diff。
按用户要求，它**不再进入例行验收**：只要守住"文本只复制粘贴、不改一个字"这条不变式，就不需要事后比对。
仅在怀疑文本被改动时（例如不是由脚本从文件灌入、而是中途手工处理过）才拿出来用。

读结果时注意两个口径：

- **页面墨迹边界**包含页码、标题、图版，不等于文本版心；要核对版心请看「文本区」那一段。
- 栏数少于设计值时，先判断是"文案没填满"（正常留白）还是"文本框丢了"（缺陷）——脚本会标 ⓘ 而不是 ★。

调用提醒：本机 PowerShell 执行策略为 Restricted，必须用 `powershell -ExecutionPolicy Bypass -File ...` 调用；直接 `.\script.ps1` 会被拒绝。

## 多页成品（杂志、画册）

逐页导出为页序命名的图片再逐页跑量测，然后额外比对跨页一致性：版心左右边界是否逐页对齐、页眉页脚基线是否跳动、跨页图是否出血连续、目录页码与内文实际页码是否一致。检查细则见 [references/checklist.md](references/checklist.md)。
