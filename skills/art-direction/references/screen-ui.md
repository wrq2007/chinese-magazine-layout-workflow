# 屏幕界面（网页 / App / UI）专项

只用于屏幕媒介。跨媒介通用的部分（层级、克制、灰阶判据、焦点唯一）见 [principles.md](principles.md)，
这里只写屏幕特有、纸上学不到也搬不过去的部分。

## 与印刷的关键差异

| 同一原则 | 印刷 | 屏幕 |
| --- | --- | --- |
| 层级靠什么 | 字号、字重、位置、留白 | 上述 + **状态与动效**（hover/focus/active 可临时提权） |
| 深度线索 | 基本不用（阴影会脏） | 边框 → 阴影 → 模糊 → 高光，按需递增 |
| 布局约束 | 固定版心、出血、装订 | 视口自适应；移动端是**重新编排**不是压扁桌面 |
| 强调色 | 受印色与成本限制 | 受可访问性对比度限制 |
| 迭代代价 | 重印成本高 | 可随时改，但不该因此容忍结构不清 |

## 状态：默认态要安静，强调留给交互

- 默认态不要用满强调；把强对比留给 hover / focus / active / selected / error。
- **selected 与 pressed 必须可区分**：一个是持续状态，一个是瞬时反馈，混在一起用户会误判。
- 加载、成功、失败三种状态都要设计，不要只做"正常态"。

## 动效：短、稳、有用途

- 只动 `transform` 与 `opacity`，不要动 `top/left/width/height`（会触发布局抖动）。
- 时长控制在能"引导感知"的范围，不要变成编排表演；动画抢戏就是失败。
- 列表/网格入场可以错峰，但不要所有元素同时漂浮。

## 深度与光：只在解释层级时使用

- 阴影/模糊/高光的作用是说明"谁在谁上面"，不是制造"高级感"。
- **发光是例外，不是结构**：到处都是 glow，等于没有重点。
- 暗色界面优先用面层级与边缘定义做深度，其次才用模糊与阴影。
- 别用渐变/发光去伪造精致——它替代不了结构，和印刷里用廉价渐变铺底是同一个病。

### 层次靠叠层，不靠阴影

"高级感"的深度来自**叠层**，不是来自更重的阴影（`shadow-lg/2xl` 这类通用阴影一眼就廉价）：

```
底层   细噪点/纸纹叠加（很轻）
中下   极淡的暖/冷渐变晕（5–15% 不透明度）
中层   装饰元素（一个超大的显示字符、一张淡化的照片、一层网格）
前景   内容
```

需要分隔时优先用 1px 边线或渐变描边，而不是阴影；阴影只用来表达真实的高度差。

## 组件工艺

- 相关控件共享一致的高度、内边距逻辑与圆角规则；先让组件精确，再让它有风格。
- 组件精修服从整页构图：单个卡片再精致，页面失衡也是失败。
- 普通卡片保持简短：强标签 + 数值 + 少量说明，不要发明填充文案。

## 设计 token：先定规则，再画界面

一套能撑住的界面，至少要先把这六类定下来（定完再动手）：

1. **色彩**：底色、面、边线、文字主/次、唯一强调色
2. **字号阶梯**：正文为基准，用固定比例（1.2/1.25/1.333）生成
3. **间距阶梯**：4/8 的倍数为一套，全站复用同一套
4. **圆角与描边**：一套值（如 4/8/12），不要每处一个新数值
5. **阴影/层级**：只允许 1–2 档，且说明它们代表什么高度差
6. **动效**：一套时长与缓动（如 200/400/800ms 三档）

界面里出现的任何颜色、间距、圆角，都应该能指回上面某一条——指不回去的，就是临场发明的，删掉。

## 布局骨架

- 整页默认铺满视口宽度，不要缩成一个居中的窄面板；需要约束的是**内容区**，不是整个体验。
- 平台/电商/门户类页面先展开外骨架（导航、主视觉、分类栏、活动区），再把内层模块卡片化。
- 首屏必须保住同一条主信息或主行动。

## 屏幕版反面清单

- 居中大标题 + 等分三卡（模板结构，没有阅读顺序）
- 紫蓝渐变当"科技感"、emoji 当图标、圆角卡片 + 左侧彩色描边
- 奶油白/米色打底当作"高级"的默认捷径
- 用发光、重阴影、玻璃模糊伪造精致
- 默认态就耗尽强调，交互态没有余地
- 为了不显模板化而强行非对称、制造紧张感

## 交付前自检

- 三秒内是否看得出这块界面在做什么、下一步点什么？
- 灰度截图下结构是否仍然成立？
- 相关控件是否是同一套几何与行为系统？
- 默认态是否足够安静，能把焦点让给交互态？
- 阴影与高光是在描述深度，还是在制造雾？
- 移动端首屏是否保住了同样的主信息？
- 页面里每一个颜色/间距/圆角，是否都能指回设计 token 里的某一条？
